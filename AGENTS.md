# ГНС: правила разработки

Этот файл обязателен для всех разработчиков и AI-агентов, работающих с проектом.
Перед изменением кода прочитать `docs/PRODUCT_SPEC.md`,
`docs/ARCHITECTURE.md` и `docs/DEVELOPMENT_AUTOPILOT.md`.

## Назначение

Локальное приложение для Windows автоматизирует обработку PDF-писем ГНС,
получение официального документа по QR, безопасное извлечение реквизитов,
проверку через тестовый или реальный адаптер АБС, ручное исправление
неопределённостей и создание ответа Word.

## Неприкосновенные правила

1. Ни один загруженный PDF и ни одна страница не могут исчезнуть из учёта.
2. Для каждой страницы всегда существует запись и конечный статус.
3. Нельзя угадывать символы, цифры, слова, ИНН, даты, ФИО или тип страницы.
4. Низкая уверенность означает ручную проверку, а не автоматическую подстановку.
5. Первичный источник данных - официальная версия, полученная по корректному QR.
6. Если QR не сработал, используется OCR скана.
7. Если OCR не уверен, сотрудник обозначает страницу и вводит данные вручную.
8. Решение STI-010 - необязательное приложение. Основной документ - письмо.
9. OCR решения со скана сам по себе не разрешает автоматическое создание ответа.
10. Автоответ допустим только при наличии подтверждённого письма:
    распознанного с высокой уверенностью, полученного в официальной версии
    или обозначенного сотрудником.
11. Кыргызские буквы `Ң ң`, `Ө ө`, `Ү ү` сохраняются как отдельные Unicode-символы.
    Их нельзя заменять на `Н н`, `О о`, `У у`.
12. Не применять генеративное восстановление изображений или текста:
    оно может дорисовать цифру или букву.
13. Учётные данные АБС запрашиваются перед каждой проверкой, не сохраняются
    и не попадают в журнал.
14. Ошибка или недоступность АБС не означает, что клиент отсутствует.
15. Исходные PDF неизменяемы. Улучшенные изображения являются производными.
16. Для каждого значения журналируется источник: QR, OCR или ручной ввод.

## Приоритет обработки

`QR -> официальная версия -> OCR письма -> ручная проверка`.

Решение сохраняется и связывается с письмом, но его отсутствие или плохое
качество не блокируют ответ, если подтверждённое письмо содержит все данные.

## Обязательные поля

- район и место налогового органа;
- должность адресата;
- ФИО адресата;
- один или несколько налогоплательщиков;
- наименование каждого налогоплательщика;
- 14-значный ИНН каждого налогоплательщика;
- начало и конец периода запроса;
- подтверждённая форма обращения для ответа.

Номер письма, номер и дата решения, ФИО исполнителя решения и форма контроля
не являются блокирующими полями для ответа.

## Ручная проверка

Проблемная страница должна иметь:

- превью и ссылку на оригинал;
- номер исходного PDF и номер страницы;
- причину остановки;
- выбор типа: письмо, решение, приложение, прочее;
- редактируемые обязательные поля;
- возможность добавлять и удалять налогоплательщиков;
- подтверждение сотрудником;
- историю изменений.

После подтверждения обработка продолжается с остановленного этапа.

## Критерии изменения кода

- Любая логика автоматического принятия решения должна иметь тест.
- Любая новая ветка обработки обязана завершаться явным статусом.
- Не ослаблять пороги уверенности ради количества автоответов.
- Не добавлять облачную передачу документов без отдельного решения
  информационной безопасности.
- Не добавлять реальные реквизиты пользователей или пароли в тестовые данные.
- Шаблоны Word являются внешними артефактами. Не менять оригиналы.
- Перед завершением задачи запустить тесты и проверить сценарий плохого скана.
