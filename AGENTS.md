# ГНС: обязательные правила разработки

Этот файл читается перед любой работой с проектом. Остальную документацию
загружать только по области изменения:

- `docs/PRODUCT_SPEC.md` — пользовательское поведение, QR/OCR, ручная проверка,
  АБС, ОДБ и Word;
- `docs/ARCHITECTURE.md` — статусы, БД, сервисы, хранение, интеграции,
  безопасность и упаковка;
- `docs/DEVELOPMENT_AUTOPILOT.md` — новая функция, сквозное изменение,
  крупный рефакторинг или выпуск;
- `docs/IMPLEMENTATION_STATUS.md` — текущее состояние, ограничения и приоритеты.

Для правки только документации или изолированного интерфейсного текста не
нужно читать нерелевантные документы. При противоречии приоритет имеют:
этот файл, затем спецификация продукта, затем архитектура.

## Назначение

Локальное Windows-приложение обрабатывает PDF-письма ГНС, получает официальный
документ по QR, извлекает реквизиты, проверяет их через адаптер АБС, направляет
сомнения сотруднику и создаёт ответ Word.

## Неприкосновенные инварианты

1. Каждый загруженный PDF и каждая его страница регистрируются до распознавания
   и всегда получают явный конечный статус либо задачу ручной проверки.
2. Нельзя угадывать или генеративно восстанавливать символы, цифры, слова,
   ИНН, даты, ФИО, тип страницы, текст или изображение. Сомнение означает
   ручную проверку.
3. Приоритет источников: `корректный QR → официальная версия → OCR скана →
   ручной ввод`. Расхождение источников не разрешается автоматически.
4. Письмо — основной документ. Решение STI-010 необязательно; OCR решения сам
   по себе не разрешает ответ. Автоответ возможен только по подтверждённому
   письму со всеми обязательными данными из спецификации.
5. Кыргызские `Ң ң`, `Ө ө`, `Ү ү`, а также `уулу` и `кызы` сохраняются точно.
   Замена похожими русскими буквами и словарная догадка запрещены.
6. Исходные PDF и оригиналы Word-шаблонов неизменяемы. Превью, улучшенные
   изображения, одностраничные PDF и ответы создаются как производные файлы.
7. Учётные данные АБС запрашиваются для каждой проверки, существуют только в
   памяти и не попадают в файлы, БД, журнал или тесты. Ошибка АБС не означает
   «клиент отсутствует».
8. Для каждого извлечённого или исправленного значения хранится источник:
   `QR`, `OCR` или ручной ввод, а ручные изменения журналируются.
9. Документы и рабочие данные не передаются в облачные OCR/AI-сервисы без
   отдельного решения информационной безопасности. В репозиторий не попадают
   реальные реквизиты, документы, базы, журналы, пароли и токены.

## Правила изменения

- Работать одной проверяемой вертикалью с явным критерием готовности.
- Любая новая ветка обработки завершается статусом; логика автоматического
  принятия решения покрывается тестом.
- Не снижать пороги уверенности ради количества автоответов.
- Сохранять пользовательские изменения и не очищать чужую рабочую копию.
- Для изменения кода запускать связанные тесты. Перед публикацией запускать
  полный `pytest` и сценарий плохого скана. Для правки только документации
  достаточно проверить структуру, ссылки и отсутствие противоречий.
- В отчёте указать результат, проверки, оставшиеся ограничения и решения,
  которые требуются от пользователя.
