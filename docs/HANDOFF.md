# Передача контекста между сессиями

Короткая записка для нового чата Claude Code. Читать после `AGENTS.md`.
Обновлять в конце каждой рабочей сессии.

## Пользователь и способ работы

- Владелец проекта не программист: объяснять простыми словами, по-русски,
  без лишнего жаргона. Проект изначально сделан в OpenAI Codex.
- Решено не переписывать приложение, а исправлять баги и неудобства по одному:
  программа рабочая и больше месяца накапливает рабочую базу в офисе.
- Одна доработка — одна ветка от `main` — проверка — PR в `main`.
- Коммит и push — только по просьбе пользователя. Правки `AGENTS.md` и правил
  для ИИ пользователь коммитит сам (их блокирует защита Claude Code).
- Если меняется схема или данные БД — миграция с сохранением данных,
  предупредить пользователя и напомнить про резервную копию перед обновлением.

## Ветки и среда

- `main` = версия, установленная в офисе (на 15.10.2026 — коммит `a227dba`).
  Старая точка `main` заброшена, `main` перемотан вперёд без потери истории.
- `codex/ux-workflow-redesign` совпадает со старым `main`, больше не нужна.
  Старые ветки `agent/update-current-version`, `codex/integrations-office-test`,
  `new-branch-with-fixes-445c0` не разобраны.
- Разработка на офисном ПК: код и копия базы только на **локальном** диске
  (например `C:\dev\gns`, база в `runtime\gns.sqlite3`). Сетевой диск — только
  для резервных копий: SQLite в режиме WAL на сетевом диске может повредиться.
- Рабочая база офисного приложения лежит на локальном диске.
- Тестовая копия базы помнит настройки Outlook: на время теста закрыть
  рабочее приложение и выключить автопроверку Outlook в тестовой версии.
- Запуск: `.venv\Scripts\gns-app`; тесты: `.venv\Scripts\python -m pytest -q`.

## В работе

### Ветка `fix/time-display` (отправлена, PR ещё не создан)

Проблема: время в истории и ответах показывалось на 6 часов вперёд, форматы
дат в интерфейсе были разные.

Причина: pywin32 отдаёт `ReceivedTime`/`SentOn` Outlook как местное время с
пометкой UTC, интерфейс прибавлял ещё +6.

Сделано:
- время Outlook сохраняется как настоящее UTC (`time_display.outlook_time_to_utc`);
- разовая миграция `migration.outlook_local_timestamps_fixed` в
  `database.py` исправляет старое время получения и время отправки,
  подтверждённое событием журнала `outlook_sent_confirmed` /
  `outlook_resend_confirmed`; ручные отметки не трогает;
- единый формат: `ДД.ММ.ГГГГ ЧЧ:ММ`, даты `ДД.ММ.ГГГГ`;
- фильтр истории по датам считает дни по местному времени;
- полный `pytest` прошёл; миграция проверена на копии локальной базы
  (в ней не было отправленных ответов — отправка на реальных данных не проверена).

Следующий шаг: пользователь проверяет в офисе на копии базы, что время
получения и отправки совпадает с Outlook «Входящие»/«Отправленные». Если всё
верно — создать PR `fix/time-display` → `main`, затем обновить офис
(перед этим резервная копия рабочей базы).
