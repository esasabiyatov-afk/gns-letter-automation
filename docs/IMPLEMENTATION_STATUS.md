# Состояние разработки

Дата контрольной точки: 28 августа 2026 года.

## Исправления по первому офисному тесту portable-сборки

- исправлен поиск АБС: запрос идёт POST-формой по полю
  `SearchIdentificationNo`; неожиданный HTML больше не превращается в
  «клиент не найден»;
- для OCR добавлена фактическая проверка инициализации `rus+kir` при старте,
  безопасная диагностика длительности, статуса, длины текста, классификации и
  наличия извлечённых полей без записи текста документа и реквизитов;
- если тип страницы остался `unknown`, но OCR структурно нашёл реквизиты,
  ручная карточка теперь получает их как неподтверждённые подсказки;
- временный каталог Outlook создаётся и проверяется основным процессом до
  запуска COM-worker; Windows-версия передаёт ASCII 8.3-путь, если он доступен,
  а при Unicode/слишком длинном или недоступном каталоге перебирает локальные
  fallback-папки. Worker не создаёт родительские папки, а основной процесс
  проверяет возвращённые вложения в том же представлении и очищает канонический
  staging-каталог;
- ошибка создания Outlook-черновика теперь показывает безопасный технический
  этап, на котором она возникла;
- окна WIA, Word и Outlook-черновика принудительно активируются поверх браузера
  совместимым с Windows 8.1 способом;
- исправлен отчёт версий компонентов в frozen-сборке: встроенный модуль больше
  не помечается как `not-installed` только из-за отсутствия metadata.

Исправления покрыты локальными тестами и требуют повторной проверки именно на
офисном Windows 8.1, Outlook 2013, Tolubay ABS и конкретном МФУ.

## Проверка скорости на реальных письмах

Контрольный локальный набор содержит 8 PDF и 18 страниц. До оптимизации полный
процесс занимал 879,5 секунды. После перехода на порядок `QR → официальный
документ → fast OCR`, общего высокого рендера и двух рабочих потоков повторный

## Важные ограничения прототипа

- поля из OCR скана используются только как подсказка и требуют подтверждения;
  надёжные поля официальной версии по QR подтверждения не требуют;
- никакая модель OCR не гарантирует цифры на самом плохом скане; перед ручным
  продолжением сотрудник обязан отметить посимвольную сверку ИНН, периода и
  наименований с изображением;
- повреждённый печатью QR не восстанавливается угадыванием: после безопасных
  попыток страница направляется на ручную проверку;
- подготовлена переносимая тестовая PyInstaller-сборка для Windows 8.1 x64;
  финальный установщик и WebView остаются следующим этапом;
- команда получения почты Outlook асинхронна: импорт проверяет локально
  доступные письма сразу после запуска команды, но пока не получает отдельное
  подтверждение завершения синхронизации; только что отправленное письмо может
  попасть не в текущую, а в следующую автоматическую проверку;
- отрисовка PDFium изолирована от веб-сервера отдельным процессом: авария
  нативной библиотеки на одном документе больше не закрывает приложение;
- интегрирован сменный read-only адаптер Tolubay Client Lookup 0.5.1; по
  умолчанию используется фейковый режим до офисной проверки URL, TLS и
  тестовой записи; единственная точная анкета повторно сверяется по ИНН,
  адаптер читает активные и закрытые счета, а приложение сохраняет только их
  количество без реквизитов счетов и полей анкеты. Результат остаётся `found`
  и направляется на ручное подтверждение наличия счёта;
- для подтверждённого банком просроченного сертификата `ob.tolubay.kg`
  добавлен явный локальный режим `GNS_TOLUBAY_VERIFY_TLS=false`; он ограничен
  точным HTTPS-хостом, не является значением по умолчанию и постоянно
  показывается в интерфейсе как небезопасный;
- по умолчанию Outlook не обходит диалог недоверенного сертификата; для
  согласованного офисного теста добавлен явный режим, который подтверждает
  только распознанный сертификатный диалог процесса `OUTLOOK.EXE` и постоянно
  показывает предупреждение в интерфейсе;
- WIA-сканирование покрыто изолированным тестовым шлюзом, но конкретную модель
  офисного МФУ и её драйвер нужно проверить в офисе; при несовместимости уже
  доступна ручная загрузка полученного файла;
- OCR-карточки без официального QR автоматически и последовательно
  сверяются с ОсОО.KG по ИНН; сохраняются совпадение названия и руководитель;
- несовпадение или ошибка ОсОО.KG блокируют OCR-кейс до явного решения
  сотрудника, без скрытой подмены названия;
- ручной поиск ОсОО.KG работает по ИНН и названию;
- если загрузка официального документа по QR завершается тайм-аутом, превью
  остаётся доступным, а сотрудник может перезапустить только эту страницу.
- страница с найденным QR автоматически снимается с ручной очереди, если
  официальный документ уже получен и все обязательные поля извлечены; выбор
  исполнителя не требует повторного подтверждения данных письма.

4. Проверить Tolubay Client Lookup 0.5.1 в офисной сети: подтвердить URL и
   фактическую ошибку сертификата, включить `GNS_ABS_MODE=tolubay` и при
   подтверждённом просроченном сертификате `GNS_TOLUBAY_VERIFY_TLS=false`,

## Критерий перехода к автоматическому ответу

Ответ создаётся автоматически только если:

- все страницы зарегистрированы и имеют конечный статус;
- письмо определено надёжно;
- обязательные поля получены из проверенной официальной версии либо
  подтверждены сотрудником;
- каждый ИНН содержит ровно 14 подтверждённых цифр;
- проверка АБС завершилась однозначным результатом;
- период не попадает под правило ручной обработки;
- в пакете не осталось блокирующих сомнений.

Ошибка сети, OCR, QR или АБС никогда не считается результатом «не найден».
