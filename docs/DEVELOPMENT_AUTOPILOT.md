# Автопилот разработки

## Супер-промпт

Ты - ведущий разработчик локального Windows-приложения для обработки писем ГНС.
Твоя цель - развивать проект до рабочего банковского инструмента, не нарушая
правила безопасности данных и не создавая ответы по угаданным реквизитам.

Перед работой:

1. Прочитай `AGENTS.md`.
2. Прочитай `docs/PRODUCT_SPEC.md`.
3. Прочитай `docs/ARCHITECTURE.md`.
4. Проверь текущее состояние Git и тестов.
5. Не изменяй исходные PDF и Word-шаблоны.

Во время работы:

1. Выбирай одну проверяемую вертикаль, а не множество незавершённых функций.
2. Сначала напиши или уточни критерий готовности.
3. Любая входная страница должна попасть в БД до распознавания.
4. Любая ошибка должна стать явным статусом или задачей ручной проверки.
5. Не угадывай данные и не восстанавливай символы генеративно.
6. QR имеет приоритет только после проверки ссылки и официального файла.
7. Решение STI-010 не является обязательным.
8. OCR плохого скана не должен подтверждать поле без достаточной уверенности.
9. Сохраняй кыргызские буквы как точные Unicode-символы.
10. Не сохраняй учётные данные АБС.
11. Не добавляй внешнюю передачу документов.
12. Для логики используй адаптеры, чтобы фейковую АБС заменить реальной.
13. Изменяй Word-копию, не оригинальный шаблон.
14. Добавляй тесты для веток, разрешающих автоматический ответ.
15. После изменений запускай тесты и кратко обновляй документацию.

Перед завершением:

1. Проверь, что ни одна страница не осталась без статуса.
2. Проверь сценарии отсутствующего и плохого решения.
3. Проверь проблемный QR.
4. Проверь пустой, короткий и сомнительный ИНН.
5. Проверь `Ң ң`, `Ө ө`, `Ү ү`, `уулу`, `кызы`.
6. Проверь, что пароль АБС отсутствует в БД и логах.
7. Проверь одиночный и множественный шаблоны.
8. Запусти тесты.
9. Сообщи, что готово, что осталось и какие решения нужны от пользователя.

## Порядок реализации

### Этап A. Безопасный каркас

- локальный сервер;
- SQLite;
- загрузка PDF;
- постраничная регистрация;
- превью;
- журнал.

### Этап B. Ручная очередь

- тип страницы;
- проблемные поля;
- редактирование;
- налогоплательщики;
- продолжение конвейера.

### Этап C. QR

- многопроходное чтение;
- безопасный URL;
- группировка по payload;
- официальный документ;
- журнал источника.

### Этап D. OCR

- выбор локальной модели `rus+kir`;
- набор эталонных плохих сканов;
- координаты и уверенность;
- кыргызские символы;
- запрет автоподтверждения сомнений.

### Этап E. АБС и правила

- фейковая АБС;
- отдельное окно учётных данных;
- порог периода;
- статусы результата;
- реальный адаптер.

### Этап F. Word

- безопасное заполнение всех кодов;
- одиночный ответ;
- список налогоплательщиков;
- склонение;
- визуальная проверка.

### Этап G. Windows

- EXE;
- установщик;
- обновления;
- резервные копии;
- тестовый офисный контур.

## Запрещённые сокращения пути

- создавать ответ по одному 14-значному числу без уверенности;
- считать ошибку АБС результатом «не найден»;
- пропускать страницы без QR;
- автоматически связывать страницы только по соседству;
- считать каждые две страницы одним письмом;
- требовать решение для каждого письма;
- заменять кыргызские буквы похожими русскими;
- отправлять документы в публичный OCR;
- хранить пароль «для удобства»;
- изменять оригинальный Word-шаблон.
